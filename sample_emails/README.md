# Demo fixtures

Generated by [`generate_fixtures.py`](generate_fixtures.py). All three are grounded in
DNS records that were genuinely live on **2026-09-06** (checked via `Resolve-DnsName`
before writing the fixtures) — the point is that the pipeline's SPF/DKIM/DMARC results
on these files come from real evaluation against real domains, not hardcoded outcomes.
Re-run the generator any time to rebuild them.

## clean_legit_001.eml — expect `legitimate`, score 0

From `alex.mentor@gmail.com`, relayed through `74.125.20.41` — a real address inside
Google's published SPF range (`_spf.google.com` → `ip4:74.125.0.0/16`). Real SPF
**pass**, real DMARC **pass** (via SPF alignment; gmail.com's policy is `p=none`). No
DKIM-Signature header, so DKIM is `none` — genuinely not fakeable without gmail.com's
private signing key (see the note in [../docs/build_roadmap.md](../docs/build_roadmap.md)
about live-demoing a real DKIM pass instead).

## spf_fail_spoofed_001.eml — expect `fraud`, score 90

Spoofs `security-alerts@sbi.co.in` (State Bank of India), relayed through `1.1.1.1` —
nowhere near SBI's real published SPF ranges
(`v=spf1 ip4:175.158.69.0/19 ... include:spf.protection.outlook.com -all`). Real hard
SPF **fail** against their real `-all` policy, real DMARC **fail** against their real
`p=reject` policy. Plus a `Reply-To` mismatch (protonmail.com) and credential-harvesting

## dmarc_fail_lookalike_bec_001.eml — expect `fraud`, score 100

From `billing@paypa1-secure-verification.com` — confirmed zero DNS presence (NXDOMAIN on
A/TXT/MX) on 2026-09-06, so SPF/DKIM/DMARC all genuinely evaluate to `none`. The domain
fuzzy-matches "paypal.com" (rapidfuzz partial-ratio), and the body stacks
payment-diversion + fake-invoice + executive-impersonation BEC language plus a
`.js` attachment.

## A better live demo than any fixture

Because DKIM needs a real private key to sign with, none of these fixtures can show a
genuine DKIM **pass** — only `none`/`fail`. For a live SIH demo, forward a real email
from your own Gmail/Outlook account to yourself, save it as `.eml` ("Show original" →
download in Gmail), and upload that instead: it'll carry a real DKIM signature that
the pipeline will genuinely verify against the sender's real public key in DNS.
